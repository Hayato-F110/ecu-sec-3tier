完了条件：`docker compose up` だけで全画面が動く。

「認証なし版」：Day 6 のログインの前なので、本人確認は SC3-9 と同じ仮の本人確認（ヘッダー `X-Dev-User-Id`、`DEV_AUTH_ENABLED=true` のときだけ）を使う。役割での絞り込みは、この仮の本人確認のユーザーで行う。

テストは SC3-9 と同じテスト用 DB に、ダミーデータ（`app.seed`）を入れた状態で流す。テストごとに取り消す。

## 作る API

| API | 呼べる人 | サプライヤ・ログインなし |
| --- | --- | --- |
| `GET /api/matrix` | メーカーの全員（システム管理者・確認者。仕様の画面の表の「使う役割：メーカー」） | サプライヤの全員は 403（URL に番号がないので、存在を隠す 404 の対象がない。役割で断る）。ログインなしは 401 |

応答：対策項目の一覧（並び順どおり）と、全 ECU の行。行は「サプライヤの名前・ECU の名前・品番・車種・**最新の承認済みの版**の番号と確認状況（未確認・確認完了・修正依頼中）・項目ごとの状態」。

- 承認済みの版がない ECU も行を出す（版の番号・確認状況・状態は空）。ECU はメーカーが登録するもの（仕様のマスタ管理）なので、ECU があること自体はメーカーに隠さない
- 下書き・承認待ち・差し戻しの版は、どの形でも返さない。新しい版が承認されるまで、前の承認済みの版を返す（守りの決まり4）
- 根拠の説明・対応予定日は返さない（マトリクスのセルは状態だけ。詳しい内容は ECU 詳細の画面（Day 9）で）

調べる順番：ログインしていない → 401。サプライヤのユーザー → 403（DB を読む前）。

## 作る画面

`/matrix`：一括確認マトリクス。上に、ページの切り替え（自社 ECU 一覧・一括確認マトリクス）。絞り込み：サプライヤ・確認状況（画面の中で絞る。行は最大でも ECU の数）。セルは状態を文字で出す（色だけに頼らない）。

この課題では作らないもの：「状態」での絞り込みと CSV 出力（Day 11 の CSV 出力と一緒に作る）、ECU 詳細への移動（Day 9）。
