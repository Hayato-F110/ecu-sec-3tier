完了条件：`docker compose up` だけで全画面が動く。

「認証なし版」：Day 6 のログインの前なので、本人確認は SC3-9 と同じ仮の本人確認（ヘッダー `X-Dev-User-Id`、`DEV_AUTH_ENABLED=true` のときだけ）を使う。役割での絞り込みは、この仮の本人確認のユーザーで行う。

テストは SC3-9 と同じテスト用 DB に、ダミーデータ（`app.seed`）を入れた状態で流す。テストごとに取り消す。

ダミーデータの形（test-plan-reviewer が `backend/app/seed.py` から数えた）：承認済みの版はどれも版1だけ。「承認済みの版が2つ以上」「承認待ちだけ」「差し戻しだけ」「版なし」「承認済みの上に下書き」の ECU は 0件。そのため、これらの形は**テストの中で作る**（#2・#3・#4）。期待値は実装の関数（`latest_approved` など）を使わず、テストの中の別の SQL（`max(version) WHERE status='approved'`）で求める（同じ関数で期待値を作ると、まちがいも一緒に通る）。

## 作る API

| API | 呼べる人 | それ以外 |
| --- | --- | --- |
| `GET /api/matrix` | メーカーの会社（`companies.type = oem`）に属する、システム管理者・確認者（2026-11-25 にオーナーが決めた。仕様の役割の表に書いた） | サプライヤの会社の利用者は、役割にかかわらず 403。ログインなし・無効な利用者は 401 |

役割に加えて会社の種類も確かめる理由：役割と会社の種類が合っていることを、DB の制約では守っていない（`models.py`）。ユーザー管理（今後）や手作業の誤りで「サプライヤの会社の確認者」ができたとき、全社のデータを読めてしまうため（仕様より強い条件）。

404 ではなく 403 にする理由（守りの決まり2・7の例外）：URL に ECU や会社の番号がないので、隠す相手（存在）がない。403 で分かるのは「マトリクスという機能がある」ことだけ。同じ守りは「メーカー以外は、どの会社のデータも1行も読めない」で確かめる（#8・#9）。この例外は、2026-11-25 にオーナーがこのテストの一覧（設計案）とともに承認した。この理由は、スプリント2の `docs/design-decisions.md` にも書く。

応答：対策項目の一覧（並び順どおり）と、全 ECU の行。行は「サプライヤの名前・ECU の名前・品番・車種・**最新の承認済みの版**の番号と確認状況（未確認・確認完了・修正依頼中）・項目ごとの状態」。版の番号・確認状況・状態は、すべて同じ1つの版から取る。

- 承認済みの版がない ECU も行を出す（版の番号・確認状況・状態は空）。ECU はメーカーが登録するもの（仕様のマスタ管理）なので、ECU があること自体はメーカーに隠さない。行の形（欄の集合）は、下書き・承認待ち・差し戻し・版なしのどれでも同じにする（欄のあるなしで、下書きがあることが分からないように）
- 下書き・承認待ち・差し戻しの版は、どの形でも返さない。新しい版が承認されるまで、前の承認済みの版を返す（守りの決まり4）
- 根拠の説明・対応予定日・差し戻しの理由・コメント・申請者や承認者は返さない（承認済みの版でも返さない。マトリクスのセルは状態だけ。詳しい内容は ECU 詳細の画面（Day 9））。応答の欄は決めた集合とぴったり同じにする
- 版を承認したあとで足した対策項目（承認済みの版に入力がない項目）のセルは空
- 読むだけの API なので、監査ログは書かない（守りの決まり5は状態の変更とコメントが対象）
- URL の問い合わせの値（`?supplier_id=` など）は受け取らない（絞り込みは画面の中で行う）

調べる順番：ログインしていない・無効な利用者 → 401。メーカーの会社のシステム管理者・確認者でない → 403（ECU・版の表を読む前）。

## 作る画面

`/matrix`：一括確認マトリクス。上に、ページの切り替え（自社 ECU 一覧・一括確認マトリクス）。絞り込み：サプライヤ・確認状況（画面の中で絞る。行は最大でも ECU の数）。選択肢のサプライヤは、応答の行から作る。「すべて」で全行に戻る。当たる行がなければ「該当なし」と出す。承認済みの版がない行は、確認状況で絞ったときはどれにも当たらない（「すべて」のときだけ出る）。セルは状態を文字で、確認状況も文字で出す（色だけに頼らない）。

この課題では作らないもの：「状態」での絞り込みと CSV 出力（Day 11 の CSV 出力と一緒に作る。Day 11 のテストの一覧に持ち越す）、ECU 詳細への移動（Day 9）。
