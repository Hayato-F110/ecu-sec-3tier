## 権限の表（テストの期待値。仕様「役割と権限」から）

| API | 種類 | メーカー：システム管理者・確認者 | サプライヤ：入力者 | サプライヤ：承認者・管理者 |
| --- | --- | --- | --- | --- |
| `GET /api/ecus` | サプライヤ用 | 403 | 200（自社の ECU だけ） | 200（自社の ECU だけ） |
| `GET /api/ecus/{ecu_id}/assessment` | サプライヤ用 | 403 | 自社 200・他社 404 | 自社 200・他社 404 |
| `PUT /api/ecus/{ecu_id}/draft` | サプライヤ用 | 403 | 自社の下書き 200・他社 404 | 自社 403・他社 404 |
| `GET /api/matrix` | メーカー用 | 200 | 403 | 403 |
| `POST /api/auth/login` | だれでも | （表の対象外。test_api_auth.py で確かめる） | | |

- 「種類」がサプライヤ用の API は、**サプライヤの会社**の、サプライヤの役割（入力者・承認者・管理者）だけが通る。メーカー用はその逆。役割と会社の種類の**両方**が合わなければ 403（SC3-34）
- 調べる順番（今のまま）：401 → 会社の種類と役割が合うか（403）→ 自社のデータか（404）→ 操作の役割（403）→ 本文の形（422）→ 状態（409）。他社のデータに、権限のない役割で書き込もうとしても 404 が先（存在を明かさない）
- PUT の入力者の 200 には、実在する対策項目の本文を使う（`item_id` はダミーデータの1つ目の項目）。自社の ECU は下書きだけの DMY-A004（承認待ちの版がある ECU だと 409 になるため）
- サプライヤの管理者は、自社の下書き・承認待ちの中身を読める（2026-11-26 にオーナーが決め、仕様の役割の表に書いた）

テストの中で作るもの（ダミーデータにないため）：

- 版のない A 社の ECU（#3）
- 役割と会社の種類が食い違う利用者（#9）：メーカーの会社の入力者・承認者・管理者、A 社のシステム管理者・確認者（`test_api_matrix.py` の作り方と同じ）

回す前に、各形の ECU・各役割の利用者が1件以上あることを確かめる（0件で空振りしない）。
