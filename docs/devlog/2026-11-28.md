## 失敗

- 確認の API のレビュー2回目の直しのあと、静的解析だけを流し、関係するテストを流さずにコミットした（529ea9c）。直しを戻すスクリプトの最後の「元のまま」で 14件落ちて気づいた。ログの最後の行で、DB の時刻を読む問い合わせの前に、書きかけの行（確認者だけ入って日時が空）が自動で DB に送られ（SQLAlchemy の autoflush）、「確認者があれば日時も必須」の制約に当たったと分かった。時刻を欄を書き換える前に読むよう直した（9147f90）
- 1回目に足したテスト「存在しない ECU は 404」は、API がまだないときの FastAPI の 404 で通っていた。応答の文まで比べて、実装の前に落ちる形にした

## 学び

- コミットの前のテストは、直しの大小に関係なく流す。小さな直し（時刻の取り方）でも、ORM の自動の送信で振る舞いが変わる
- 問い合わせの前に、書きかけの変更が DB に送られることがある。書く順番に意味があるときは、先に読むものを全部読んでから書く（車載で、複数のレジスタを書く途中に割り込みで読まれるのと同じ）
- 「存在しない」のテストは、状態の番号だけでなく応答の文まで比べる。番号だけだと、別の理由の同じ番号ですり抜ける

## 学んだこと 3 行

1. コミットの前のテストは、直しが小さくても必ず流す（529ea9c で 14件落ちていた）
2. ORM は問い合わせの前に書きかけの変更を DB に送ることがある。読むものを先に読んでから書く
3. 「ない・断る」のテストは、状態の番号に加えて応答の文も比べる（別の理由ですり抜けないように）
