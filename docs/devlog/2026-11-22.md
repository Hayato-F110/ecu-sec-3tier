## 学び

- 前のプロジェクトの Hook は、ほとんどがそのまま使えた。変えたのは「何を長い処理・コードの場所とみなすか」と「課題キー」だけ。決まりを設定のファイル（`project.json`）に出しておくと、次の引き継ぎが楽になる
- 守りの決まり（職務分離）は、API だけでなく DB の制約でも二重に守ると、API の不具合があっても壊れたデータが入らない。車載で言えば、ソフトの範囲チェックとハードの保護（MPU）を両方置く多層防御と同じ
- 検査の仕組み（Hook）は、止めすぎると使う人が無視するようになる。誤検知のテスト（止めてはいけない例）も、検知のテストと同じだけ用意する
- 作業時間は人の記憶ではなく記録（会話の時刻）から求める。車載の工数管理でも、ツールの記録から求めるほうが見積もりの見直しに使える

## 学んだこと 3 行

1. 守りの決まりは API と DB の制約の二重で守る（ソフトの範囲チェックと MPU の多層防御と同じ）
2. 検査の仕組みは、止めてはいけない例のテストも用意しないと、誤って止めて無視されるようになる
3. 外部サービスの画面の手順は記憶で書かず、公式の資料で確かめて出典を添える
