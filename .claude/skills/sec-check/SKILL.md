リポジトリ全体と、今の変更のセキュリティを確かめてください。対象は自分のリポジトリだけです。

1. **秘密情報**
   - `git ls-files` に、追跡すべきでないファイル（`.env`、`*.pem`、`*.key`、`*.tfstate`、`*.tfvars`、トークン、認証情報）がないか
   - 追跡中のファイルに、鍵やトークンらしい文字列（`AKIA`、`-----BEGIN`、`ghp_`、`password=`、`SECRET_KEY=` の値など）がないか。`env.example` の値がダミーか
   - `.gitignore` と `.claude/settings.json` の deny に漏れがないか
   - 見つけたら値は書かず、場所だけを報告して止まる（CLAUDE.md「必ず止まる」2）
2. **人と会社の情報**
   - 人の名前（`git log` の作者名・メールも含む）、会社の情報・実在の ECU の情報が、ファイル・コミット・PR・ダミーデータにないか
3. **データ分離と認可**（このシステムで一番重要）
   - API の一覧（FastAPI のルーター）を全部挙げ、各 API について：認証が要るか、役割の確認、会社での絞り込み、他社は 404 か、それを確かめるテストがあるか、を表にする
   - 状態の変更（申請・承認・差し戻し・確認完了・修正依頼）を API 側で検証しているか。職務分離（申請者本人は承認できない）
   - JWT：署名のアルゴリズムの固定、期限、鍵の置き場所。パスワード：bcrypt
4. **危険なコード**
   - SQL の文字列の連結、`eval`・`exec`、`subprocess` のシェル、`dangerouslySetInnerHTML`、CSV 出力の数式の注入（`=`・`+`・`-`・`@` で始まるセル）
   - CORS の設定（nginx で同じオリジンにしているか。`*` を許していないか）
5. **CI と公開**
   - `.github/workflows/`：`permissions` が必要な分だけか、外部のアクションがコミット ID（SHA）で固定されているか、秘密情報を使っていないか
6. **依存関係**：`uv run pip-audit`（入れていれば）・`npm audit`、版が固定（`uv.lock`・`save-exact`）か、新しい依存の公式の変更履歴・セキュリティ情報を確かめたか
7. **AWS**（`infra/` があれば）：RDS がプライベートサブネットか、セキュリティグループで開けているポートと送り元、22番ポートを開けていないか、S3 のパブリックアクセスのブロック、CloudFront の OAC（S3 を直接公開しない仕組み）、IAM のポリシーが必要な分だけか、費用ゼロのガードレール
8. **AI と道具**：Jira の MCP の削除系が deny のままか、Hook がすべて `settings.json` につながっているか

報告は「重大度（高・中・低）／場所（ファイル:行）／内容／対処案」の表にする。deny で読めないファイルは、読もうとせず「読めないので未確認」と書く。
直すのは、表を示したあと（秘密情報・公開範囲・履歴の書き換えはオーナーの承認を取ってから）。
