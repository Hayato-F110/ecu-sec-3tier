変更をレビューしてください。対象：$ARGUMENTS（指定がなければ `git diff` と `git diff --staged`。変更がなければ main との差分 `git diff main...HEAD`）

次の順で報告する。

1. **良い点**（具体的に。なぜ良いのかも）
2. **直すべき点**（重要な順。各項目に「ファイル名:行番号」「理由」「直し方」）
3. **プロジェクトのルールとの照合**（CLAUDE.md「このシステムの守りの決まり」）
   - 会社ごとのデータ分離：すべてのクエリが、ログインユーザーの会社で絞り込んでいるか（メーカーの役割を除く）。ID だけで引いていないか（IDOR：ID を書き換えて他人のデータを読む攻撃）。コメント・差分・CSV 出力も同じか
   - 他社のデータに 404 を返しているか（403 で存在が分からないか）
   - 状態の変更を API 側で検証しているか（承認済みの版の編集、申請者本人の承認、理由のない修正依頼、状態の飛ばし）
   - 承認済みの版を上書きしていないか。新しい版を作っているか
   - 状態の変更とコメントを監査ログに残しているか
   - 認証：未ログインで 401、パスワードは bcrypt、JWT の検証（署名・期限・アルゴリズムの固定）
   - テストが先に書かれ、他社のユーザーで呼んで 404 になるテストがあるか
   - 数値・設定が設定のファイルにあり、秘密情報が `.env`・SSM から読まれているか
4. **安全**：秘密情報、人の名前、会社の情報、SQL の組み立て（文字列の連結でなく、パラメータを使っているか）、XSS（`dangerouslySetInnerHTML`）、CORS の設定、依存の版（固定か、公式の変更履歴・セキュリティ情報を確かめたか）
5. **費用**（`infra/` を変えたとき）：CLAUDE.md「費用ゼロのガードレール」に反していないか
6. **学びのポイント**を1つ（C言語・車載ソフト開発との比較で、短く）

指摘は読んで確かめた事実に基づき、推測はその旨を書く。指摘がなければ無理に作らない。コードは変更しない。
データ分離・認可の細かい確認は `security-reviewer`、Terraform の費用・公開範囲は `aws-cost-reviewer` のサブエージェントに任せてもよい。
