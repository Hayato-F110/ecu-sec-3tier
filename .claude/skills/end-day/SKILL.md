1日の作業を終えます。次の順で進めてください。

1. `date` で日付と時刻を確かめる。日付は 0 時で区切らず、`/end-day` を実行するまでを同じ日として扱う
2. 今日の作業を把握する：前回の devlog を最後に変えたコミット（`git log -1 --format=%H -- docs/devlog`）から先の `git log --oneline`、`gh pr list --state all --limit 20`、`git status`、この会話の内容
3. **AWS を使った日なら**、`/aws-session 終了` の手順が済んでいるか確かめる（`terraform destroy` の結果、残っているリソースがないこと、その日の使用量）。済んでいなければ、ここで先に行う
4. `docs/devlog/YYYY-MM-DD.md` に追記する（なければ作る）
   - **やったこと**：Day 番号、課題キー・PR 番号・検証の結果（テストの件数、画面・API で確かめたこと）を事実で
   - **実際の作業時間**：オーナーに聞かず、Claude の会話の記録（`~/.claude/projects/<このプロジェクト>/*.jsonl` の timestamp）から求める。その日の最初と最後の時刻と、30分を超える空白を除いた合計を書く（2026-11-22 にオーナーが決めた。計画は1日5時間。見積もりの見直しの材料）。時間は「4時間44分」「55分」の形で書き、「4.69 時間」のような小数にしない（2026-11-25 にオーナーが決めた）
   - **失敗**：何が起き、実際の値・ログで何が分かり、どう直したか
   - **学び**：次に同じことをするとき何を変えるか。仕事（車載ソフト開発）に持ち帰れるものがあれば添える
   - **AWS**（使った日だけ）：残りのクレジット、その日の使用量、destroy の結果
5. `docs/handoff.md` を書き直す（次のセッションが最初に読む。今の状態だけ）：いまの状態、作業中のブランチと PR、明日の Day 番号と作業順、つまずき防止のメモ、オーナーにお願いすること。最終更新の時刻を `date` の値で書く
6. Jira：今日作業した課題の状態をそろえる（「未着手」「進行中」「完了」を名前で指定）。実際の作業時間を記録する。完了にするのは、PR をマージして完了条件を確かめたものだけ（`getJiraIssue` で完了条件を読み直し、条件ごとに証拠を付けた表を課題のコメントに書く。未達が1つでもあれば完了にしない）
7. **スプリントの最終日なら**（Day 3・6・9・12・15・18）、ここで `/design-decisions` と `/retro` を行う。次のスプリントの作業はそのあと
8. コミットしていない変更を、作業ブランチでコミットし、PR を作る。CI が緑ならマージする。**devlog と `docs/handoff.md` は、`origin/main` から作った文書だけのブランチ（`feature/SC3-xx-end-day`）でコミットし、その日のうちに PR を出してマージする**。作業中の課題のブランチには入れない（2026-11-27 に SC3-38 のブランチに入れ、その PR がマージされるまで main に devlog が出なかった。2026-11-28 にオーナーが気づいた）。最後に `git ls-tree origin/main docs/devlog/` で今日の devlog が main にあることを確かめ、手順 10 の表の証拠に書く
9. 会話に、次を出力する
   - **今日学んだこと**（表）：「流行の技術」「Claude の使い方」「セキュリティ」の3つに分けて、それぞれ2〜4行。実際に今日使ったもの・起きたことだけを書き、仕事（車載ソフト開発）での使いどころを添える。セキュリティは ISO/SAE 21434・TARA との対応を一言
   - **学んだこと3行**（devlog の「学び」から選ぶ）。会話に出す前に、devlog の「## 学んだこと 3 行」の節に書いて、手順 8 のコミットに含める。会話では3行を示し、「devlog に反映しました。もし変更の依頼があれば返信してください。」と添える
   - 今日の進捗（計画どおり／遅れ：何が・どれくらい）と、明日の最初の作業を3行で
10. 最後に、手順1〜9の**済み・未済の表**（列：手順｜済み／未済／対象外｜証拠〔ファイル・コミット・課題のコメント〕）を会話に出す。未済があれば、その理由と、いつ行うかを書く。途中で止まった `/end-day` を次の会話で仕上げるときも、この表で残りを決める（2026-11-23：前日の `/end-day` の残りを仕上げたとき、手順9の報告を飛ばしたため。オーナーが決めた）

devlog と handoff には、人の名前（「オーナー」と書く）、会社の情報、秘密情報を書かない。
